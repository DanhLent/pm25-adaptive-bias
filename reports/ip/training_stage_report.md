## What training means

Training selects the lightweight learning behavior: the update rule, a power-of-two alpha, preliminary bounds, thresholds, scale, update timing, and validity behavior. It produces a configuration and trace rather than a trained neural-network file.

The current recurrence is:

    residual[t] = purpleair_pm25[t] - cams_pm25[t]
    bias[t+1] = bias[t] + alpha * (residual[t] - bias[t])
    fused_pm25[t] = cams_pm25[t] + bias[t]

The sample trace uses the bias before the current update for the current fused output. A row with qc_ok equal to zero holds the bias.

## Why it is FPGA-friendly

Every alpha candidate is a reciprocal power of two. The selected alpha can later use an arithmetic right shift instead of a general multiplier. The base model needs signed subtraction, addition, shift, state, saturation, and comparisons.

The exported .vh file contains only preliminary local parameters. It does not contain a module and is not an RTL implementation.

## How self-learning remains on FPGA

Python chooses how the adaptive state should behave. It does not precompute all future corrections. The later FPGA receives new CAMS/PurpleAir samples and updates learned_bias after deployment. An optional 24-entry hourly profile may later update in the same online manner.

Thus the FPGA remains adaptive even though the learning-rate constant is selected offline.
