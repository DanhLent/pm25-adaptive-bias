# RTL Quality and Verification Plan

## Purpose

This note records the quality-review direction for the first `pm25_alert_core` RTL implementation. The core is intentionally small because the frozen v1 algorithm is small: signed integer add/subtract, arithmetic shift, saturation, threshold classification, and one alert-state hysteresis bit.

Small RTL is acceptable here. The important question is not line count; it is whether the implementation is readable, synthesizable, state-timed correctly, and checked against the Python fixed-point contract over enough meaningful cases.

## Naming decision

The first RTL quality pass kept the original descriptive names. The later strict style pass shortened names where that improved readability without changing behavior:

| File | Reason |
| --- | --- |
| `pm25_alert_core.v` | Clearly identifies the top-level arithmetic IP core. |
| `bias_update.v` | Shorter than the original `adaptive_bias_update.v` while still describing the adaptive-bias stage. |
| `fusion.v` | Shorter than `fusion_saturate.v`; the clamp behavior is documented in the module purpose. |
| `alert_classifier.v` | Clear and short enough. |
| `hysteresis.v` | Shorter than `hysteresis_update.v` and still specific in this core folder. |
| `pm25_constants.vh` | Shorter than `pm25_core_v1_constants.vh` while still project-specific. |

The CSV column names remain unchanged because they are part of the Python vector contract.

## Module responsibilities

| Module | Responsibility |
| --- | --- |
| `pm25_alert_core` | Registers outputs, stores learned-bias and hysteresis state, and enforces pre-update bias timing. |
| `bias_update` | Computes residual, error, accepted flag, signed-shift delta, and saturated next learned bias. |
| `fusion` | Computes fused raw PM2.5 from CAMS plus pre-update bias and clamps to the PM2.5 output range. |
| `alert_classifier` | Maps saturated fused PM2.5 to the frozen alert-level encoding. |
| `hysteresis` | Updates or holds the binary alert state. |
| `pm25_constants.vh` | Defines frozen localparam constants only. |

## RTL review checklist

The quality review focuses on these points:

- current fused output uses `bias_state_x16` before the current update;
- learned-bias state updates only through the saturated `bias_after_x16` path;
- `qc_ok = 0` holds bias but still allows a valid fused output when `sample_valid = 1`;
- `sample_valid = 0` sets `result_valid = 0`;
- invalid samples hold hysteresis;
- `accepted = sample_valid && qc_ok`;
- `delta_x16 = error_x16 >>> BIAS_SHIFT`;
- negative arithmetic shift matches Python `>>`;
- bias saturation clamps to `BIAS_MIN_X16` and `BIAS_MAX_X16`;
- fused PM2.5 saturation clamps to `PM25_MIN_X16` and `PM25_MAX_X16`;
- alert classification uses inclusive `<=` thresholds;
- hysteresis turns on at `ALERT_ON_X16` and turns off at `ALERT_OFF_X16`;
- combinational modules assign defaults and do not infer latches;
- sequential logic uses nonblocking assignments;
- signed datapath declarations are explicit.

## Extra vector coverage

The extra vectors are generated by `python_model/fixed_point/generate_extra_test_vectors_v1.py` into `data/test_vectors/extra/`. They use the same CSV column contract as the original vectors and are produced by the existing Python fixed-point reference.

| Vector | Main purpose |
| --- | --- |
| `extra_long_positive_adaptation.csv` | Long positive residual adaptation over at least 128 samples. |
| `extra_long_negative_adaptation.csv` | Long negative residual adaptation over at least 128 samples. |
| `extra_qc_burst_hold.csv` | Bias hold through long valid-but-QC-failed bursts. |
| `extra_invalid_burst_hold.csv` | Bias and hysteresis hold through invalid bursts. |
| `extra_threshold_chatter.csv` | Hysteresis behavior around alert on/off thresholds. |
| `extra_saturation_edges.csv` | PM2.5 and learned-bias clamp behavior near edges. |
| `extra_signed_shift_edges.csv` | Arithmetic right-shift behavior for small positive and negative errors. |
| `extra_random_stress_seed_1.csv` | Deterministic pseudo-random stress with invalid, QC-failed, threshold-crossing, and negative-residual cases. |

## How to run verification

Regenerate extra vectors:

    python python_model/fixed_point/generate_extra_test_vectors_v1.py

Run Python reference tests:

    python python_model/fixed_point/test_pm25_core_v1_fixed.py

Run all original and extra vectors with Icarus Verilog:

    bash sim/run_all_core_tests.sh

On Windows machines with ModelSim ASE available, the helper batch runner can be used instead:

    sim\run_modelsim_core_tests.bat

Both RTL runners compile the core/testbench once and then execute each CSV vector through the same self-checking testbench.

## Plot review traces

`python_model/plot_vector_traces.py` creates quick PNG plots under `reports/figures/` for selected original and extra vectors. The plots show:

- `fused_pm25_x16`;
- `learned_bias_after_x16`;
- `alert_level`;
- `hysteresis_alert_after`.

The script prefers pandas and matplotlib when available. If they are unavailable, it can use a small Pillow fallback renderer. These plots are human review aids only; CSV simulation remains the correctness gate.

## Remaining work before UART demo

Do not add board-facing logic until the arithmetic core remains stable under regression. The next task, after core tests pass, should be the laptop-only UART wrapper:

- UART RX/TX;
- ASCII packet parser for x16 input fields;
- laptop Python feeder/logger;
- Tang Nano 9K top-level wrapper that instantiates the already-verified `pm25_alert_core`.

No external LED module, OLED, sensor hardware, ESP32, or extra peripheral is needed for the planned demo direction.
